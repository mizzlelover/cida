## symptom

下列写法常被当成「AI 痕迹」，但现有证据不支持拿它们当改写理由。
清单管的是改稿动作：看到这些现象，默认保持原文；若要改，举证责任在
主张修改的一方，且必须指出这条句子本身的具体问题，不能只说「像 AI」。

**语料实测站不住的（lieflat 两轮对照与 270 对配对复测）**

| 看着像 | 实测结论 |
|---|---|
| 句长、段长不够参差 | 人机离散度无差别。不为制造节奏调句长或拆段 |
| 序数词小标题 | 配对复测方向反转，已列入 X 级，永不执行 |
| 「这意味着」「这表明」式复述 | 配对复测三项口径反向，人类用得更多 |
| 空转句引列表 | 第一轮测出高倍率，配对复测方向反转，目录式长文里的正常写法 |
| 同段已有数据时仍用概括词 | 配对复测净零，不作为改写理由 |
| 句内同构排比 | 人类用得不比 AI 少 |
| 问句、设问、问句小标题 | 人类远多于 AI，删掉更不像人写 |
| 比喻、比喻独立成段 | 人类用得比 AI 多 2.4 倍、8 倍 |
| 被动句 | 抽象被动远低于收录门槛；追责场景另按主体清晰度处理 |
| 名词化、长句本身 | 现代汉语书面语的正常写法 |
| 正文「首先……其次」 | 与人类型文本无差别 |
| 反复写全称、少用代词 | 人类比 AI 更常重复同一名词 |

**维基指南列为无效指标的**

完美语法、正式或学术腔、孤立出现的过渡词、无来源内容、正确的排版标记、
口语与书面语混用。指南同时写明人类分辨 AI 文本的能力不优于随机，
并列出「Signs of human writing」：简单系动词、朴素动词
（wrote 而非 authored）、最高级与确定表述、very / perhaps / tends to
一类限定词、as a result of 等略显啰嗦的结构，在人写文本里更常见。

**工具侧不能迁移的部分**

英文超额词表（delve、pivotal、robust 等）来自 PubMed 与论文语料，
中文没有对应测量；「删掉所有副词」「一律改主动语态」「一律删破折号」
「按 0–100 痕迹分强制重写」「承诺过检」都没有中文语料支撑。

## why_it_hurts

拿这些当改写理由，改出来的稿子会更差。为参差而调句长，得到的是
机械的忽长忽短；删问句和比喻，删掉的恰好是人写文本里更常见的东西；
把被动句一律改主动，会破坏公文、学术、技术文档要求的语体；
把「可能」顺手改成确定，已经不是去味，是篡改判断强度。

更根本的一层：这些动作把「看起来不像机器」当成质量目标，
于是每一次改写都在削掉具体信息、作者习惯和文体合法性，
最后把有个性的稿子刮成通用短文。任务书 §3 已经把
「故意制造不完美」「随机扰乱语法」「删除所有结构」「禁止所谓 AI 高频词」
列为非目标，本文件是这条原则在改稿环节的可查落点。

## possible_mechanism

- 把启发式当军规：一份清单在英文、某一体裁里成立，被直接搬到所有中文文本。
- 把统计差异当来源证据：频率高低说明写法分布，不说明这句话由谁写、
  也不说明它该不该改。
- 把清洗工具的目标带进来：目标是过检测时，任何可见特征都会被当成敌人。
- 单篇诊断只看得见局部，把「这一段有两处」误当成「整篇有问题」。
- 没有回归机制时，修一个问题会制造另一个问题，且没人发现（补丁 §28）。

## repair

**先分任务类型。** 以去表层痕迹为目的的局部清理，遵守本清单与下面三条硬边界；
经用户明确授权的深重写、平台适配、结构重建，按
`../../workflows/deep_rewrite.md` 和 `../../workflows/platform_task_contract.md`
执行，改结构必须另有任务与文本依据，不能用「像 AI」当理由。

**三条硬边界，优先于任何去味规则。**

1. 信息守恒。不新增原文没有的事实、数字、名字、日期、引语、出处、因果、
   动机、场景。改写后每个实词要能在原文指出出处。反方向同样禁止：
   不删观点、结论、限定和让步，不把「可能提升」写成「提升」。
   无来源的权威背书保留其笼统和不确定，不补身份、不升格为事实。
2. 最小改动。命中规则的句子只改解决该问题所必需的部分，不顺便润色，
   不替换没问题的词，不调整详略。拿不准就保持原文。
3. 局部清理不动结构。标题层级、章节顺序、段落数量与顺序、列表、表格、
   引用、代码块位置保留；引语、代码、URL、路径、YAML、数据逐字不改。
   深重写的结构改动另按上段处理。

**仲裁顺序**（冲突时靠前的优先，取自 `Humanizer-zh` 与 `LifelongLazyLearner/qu-ai-wei`
的共识，与辞达 P0–P4 一致）：

事实、原意、证据强度、引用绑定与逻辑关系 → 用户指定的用途、语体与编辑范围
→ 作者真实声口、判断、感受、不确定性 → 自然清楚的中文表达
→ 原句式、原段序、标题与格式。

**作者声音压过清单。** 有风格样本时先读样本；作者本人惯用的破折号、
排比、重复、碎句、加粗，按样本频率保留，不按清单删，
见 `../../workflows/style_calibration.md`。校准集三级区分照 v1.2.0 执行，
辞达自己的产出不用来校准「个人声音」。

**改完回读。** 每处改动能否指出对应的具体文本问题；
实词是否都有出处；有没有为了变化而制造参差；
有没有把有依据的态度改成安全圆滑的公关语言。

## exceptions

本清单不保护真正的表达问题，只禁止用「像 AI」这个理由去处理它：

- 相邻句共用同一句法骨架、逗号数与成分顺序都相同，属
  `structural_monotony.md` 与 `account_level_monotony.md`，按具体机制改句内，
  仍不删信息、不动段落顺序。
- 比喻贴切度、拟人化喻体，模型判断不可靠，交人审；不自动改、不评级。
- 被动句把责任人藏起来、而文章正在追责时，按主体清晰度处理，
  理由写成「谁做的没交代」，不写成「被动像 AI」。
- 装饰性加粗、emoji、感叹号成灾时，按 `chinese_surface_tells.md` 第六族
  按阅读功能取舍；标题、清单、警告里帮助定位的加粗保留。
- 破折号密集到妨碍理解时逐处判断，删掉不承担解释、插入、转折功能的，
  保留作者习惯与真实语气，见 `chinese_surface_tells.md` 例外段。
- 规则随模型与语料变化会失效。新证据出现时走
  `../../workflows/self_iteration_audit.md` 修订，并过回归，不就地改口径。
