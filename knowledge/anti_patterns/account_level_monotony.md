# Account-level Monotony · 账号级同构

```yaml
name: Account-level Monotony
aka: 跨篇同构 / 账号流水线感
scope: 跨文章（单篇结构单调见 structural_monotony.md）
```

## symptom

- 同一账号近期多篇文章共用同一个骨架（如"新闻开头 → 先给答案 → 分类拆解 →
  泼冷水 → 与你何干 → 提问收尾"）；
- 首节标题反复同名（"先给答案""先说结论"），开头句式反复同款（"X 月 X 日，某公司……"）；
- 收尾动作公式化：连续多篇以"评论区聊聊""欢迎补充"式邀请结束；
- 同一种强化形式跨篇复现：每篇都有 2–5 个"加粗 + 对仗 + 独立成段"的格言句；
- 同类体裁共用同一条叙事弧（工具复盘永远是"做出来 → 撞 bug → 排查 → 修复 → 感悟"）。

## example

```
同一天的两篇新闻解读：
A 篇：一、先给答案 → …… → 六、必须泼的冷水 → 评论区聊聊
B 篇：一、先给答案 → …… → 泼完冷水 → 值得留下来的东西 → 评论区聊聊
单看每篇都合格；连起来读，像同一档节目的两期。
```

## why_it_hurts

单篇诊断看不见这个问题——每篇内部结构都清晰、修辞都稀缺。
伤害发生在老读者身上：关注者是一场长期对话的参与者，当他第三次看到同一个开头句式、
同一个首节标题、同一个收尾动作，"有一个具体的人在认真聊"的在场感就坍塌成
"流水线在出稿"。**账号的可预测性，是对话感在跨篇尺度上的流失。**
参见 `../mechanisms/account_conversation.md`。

## possible_mechanism

- 单篇优化各自收敛到"当前任务的最稳妥解"，而同一类任务的最稳妥解往往是同一个；
- 上一篇被验证"效果不错"的骨架，被当成下一篇的默认起点；
- 自检只覆盖单篇文本，没有跨篇比对环节，惯性无从暴露。

## repair

1. 成文前做**近期发布回顾**（见 `workflows/platform_task_contract.md` §2.1）：
   提取近 3–5 篇的开头类型、骨架、首节标题句式、收尾动作、强化形式；
2. 候选策略比较时，把"与近期文章的差异度"列为选择标准之一：
   新稿至少在开头类型、骨架、收尾动作、强化形式中的 2–3 个维度主动变化；
3. 同类体裁准备多条合法骨架，轮换使用；上一篇的感悟句型不写进下一篇；
4. 已经在连载的系列（如"AI 使用现场"），系列内保持识别度靠固定栏目元素，
   不靠固定句式——栏目标签可以重复，表达动作要变化。

## exceptions

- 用户明确要求系列化模板（固定栏目格式、日更固定结构）时按任务执行；
- 法律、公告、固定栏目体等要求一致格式的场景不适用；
- 账号级差异不意味着刻意避讳所有重复：真实稳定的个人声音（判断方式、价值取向）
  应当跨篇一致，需要变化的是**表达动作**，不是人格。
