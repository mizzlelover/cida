# Listicle Tendency · 清单化倾向

```yaml
name: Listicle Tendency
aka: "三个原因告诉你"式伪结构
```

## symptom

- 标题或开头先承诺数量——"三个原因""五个方法""N 个信号告诉你"；
- 每个点只有一句结论加一句解释，彼此并列、没有递进；
- 点为凑数而存在：删掉其中任意一个，全篇信息量几乎不变；
- 收尾把 N 点再重述一遍，凑出"完整感"。

## example

```
为什么你总是读不完一本书？三个原因告诉你：
一、没有目标。没有目标的阅读，就像没有目的地的旅行。
二、时间不够。碎片时间被短视频占满，阅读自然被挤走。
三、方法不对。逐字读、必须读完，只会让负担越来越重。
```

三点之间没有递进，任意删去一点，读者获得的信息几乎不变。

## why_it_hurts

清单化把"结构"当成"价值"：**数量承诺替代了判断承诺**。读者被标题吸引，得到的却是
可预期、可互换的并列条目——读第一点就能推出第二点的写法。真正的认知推进被"凑够 N 个"
的格式需求压平，作者也不必被迫做出取舍。

## possible_mechanism

自媒体的"可预期性红利"：固定数量 + 编号让读者预知阅读成本、降低点开门槛，也便于拆分传播。
对写作者而言，**先定数量再填内容**是最省力的默认解——不必先有判断，只要凑够条目。

## repair

1. 先问"这些点里哪一个是真正的判断"，把它提为主线，其余降为支撑或删除；
2. 允许点与点之间有递进（前提→机制→边界），而不是平铺；
3. 数量服从内容：两点就写两点，不必凑三点；
4. 标题改为可证伪的判断句，而不是数量承诺（"读不完书，多半是目标先没了"）。

## exceptions

- 清单式教程、速查表、操作步骤**要求**可枚举，不适用本条；
- 内容确实由 N 个独立并列项构成（如"N 个必备工具"）时，清单是忠实形式，不是病灶。
