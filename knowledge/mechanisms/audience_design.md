# Audience Design · 受众设计

```yaml
id: mech.audience_design
name: 受众设计
function: 按受众知识、关系和场景调整表达而不改变事实
confidence: validated
```

## definition

受众设计不是迎合，而是选择读者已知锚点、解释坡度、互动距离和责任语气。

## mechanism

先识别受众知识与反对点，再调十维 Profile；同一主张可改变入口、例子和节奏，不可随意改变证据。

## realizations

技术文面向普通人补一个动作例子；知乎提高证据密度；小红书缩短块面；政策答复显式写条件。

## boundary_conditions

不同受众不能被假设成同一群体；平台参数不能替代任务目标。

## overuse_risk

过度受众化会把复杂事实降成口号。

## repair_strategy

记录一次受众假设和一个可验证反馈点，发现不符就调整 Profile。

- 跨来源比较——**受众设计的作用点不同**：
  1. 周轶君（演讲体）：作用点在**收束**——"更多的希望我觉得是在在座的每一位"，把结论转交听众；
  2. 《新闻1+1》20130730（电子媒体）：作用点在**框定与分工**——以"我们每个人的安全"框定受众，并把公安（执行层）与学者（归因层）分设两条连线；
  3. 陈晓卿（演讲体）：作用点在**接受方式**——显式允许"当作品看"与"当娱乐消遣产品看"两种读法；
  4. 何（娱乐聊天室，2026-09-17 第三十七批补）：作用点在**节目形态**——把"风格"改写为"随节目内容调整状态"，并给外景／明星访谈两套不同的准备与控制参数；
  5. 康辉（文化节目，**第四十四批补**）：作用点在**参与方式**——**自嘲式拉平**降低发言成本（第二集）、**把选答者权力交给观众**（第九集）。
  五者共同落点即本页 definition「选择读者已知锚点、解释坡度、互动距离和责任语气，而不改变事实」；差异在**设计动作发生在何处**（收束／框定分工／接受方式／节目形态／参与方式）。
- 边界：五例均为口语语域（多例 `scripted`；何炅条为**嘉宾自述**）；本页 `realizations` 所述**平台适配动作（公众号缩块、小红书缩短、政策答复写条件）仍未经语料验证**，故 `validated` 指**机制成立**，不等于各平台的受众参数已校准——那属 Style Control Space（待人工评测）。
