# Clarification · 澄清

```yaml
id: mech.clarification
name: 澄清
function: 消除术语、代词或推理中的多义而不打断流动
confidence: validated
```

## definition

澄清不是把所有概念写成词典定义，而是在误解概率高的地方补上最小必要信息。

## mechanism

识别读者可能的两种解释，先指出容易混淆的边界，再给当前文本采用的含义；把澄清放在第一次影响判断的位置。

## realizations

文章用‘这里说的X，不是A，而是B’；访谈用复述确认；播客用例子回检；正式文本用定义和适用范围。

## boundary_conditions

专家受众已共享的术语不需过度解释；法律、医疗、政策概念必须保留正式定义。

## overuse_risk

层层定义会产生百科腔，遮住主线。

## repair_strategy

只保留会改变读者下一步判断的澄清，并用一个具体例子落地。

## 跨来源验证（§121）

- 状态：`validated`（2026-09-16 登记）。本批补齐「专家侧 + 主持侧」两侧样本。
- 依据（§121 二选一取后者）：**理论**＝何自然语用学、冯胜利语体语法；**语料样本**＝王辰（答问体·专家侧）、董倩（评论体·主持侧），**2 位表达者、2 语域**。
- 跨来源比较——**"在第一次影响判断的位置补最小必要信息"跨角色收敛，差异在澄清者是谁**：
  1. **以分类消解模糊概念**（王辰，专家侧）：把"疑似病例"劈出一类——"临床诊断病例，也就是在流行病学史和临床表现上和确诊病例高度吻合"；
  2. **以"需要指出的是"纠正流行误读**（王辰）：先纠正"并非所有患病者都能检出核酸阳性"（检出率约 30%–50%），再给建议；
  3. **主持侧先校准事实**（董倩，主持侧）："12 年这两种死刑方式一直在并行地推进的话，**选择的不是说是犯人去选择，而是说由执行的这个单位去选择**"——先消除一个流行误解，再让解释有落点。
  三者共同落点＝本页 mechanism「把澄清放在第一次影响判断的位置」；差异在**澄清者角色**（专家自澄清／主持人代公众澄清）。
- 边界：① 两例均为 `prepared`／`official` 文本，**即兴对话中的即时澄清未覆盖**；② 医学概念须保留正式定义（`boundary_conditions`），本节点只取**澄清手法**，**不为医学结论背书**；③ `overuse_risk`（层层定义→百科腔）未做反例抽样。
