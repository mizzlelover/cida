# Irony · 反讽

```yaml
id: mech.irony
name: 反讽
function: 借表层话语与语境之间的张力暴露矛盾，但不让读者误认作者立场
```

## definition

反讽不是把话反着说，而是让读者同时看到字面说法、现实证据和两者的落差。
落差必须可由语境和事实回收，不能依赖读者猜作者心情。

## mechanism

表层命题→语境提示→证据落差→明确回扣。文本越短、受众越陌生，越需要显式标出反讽的目标
与边界。

四步中最后一步尤其重要：需要让读者在文本中看见反讽所指的落差。没有回扣，
读者可能只看到字面意思，无法确认作者的真实立场。

## realizations

评论可用引号、并置事实或克制的反问揭示口号与结果的差异；访谈中先复述对方命题，再让
后续事实显出不一致，避免凭语气暗示。

常见实现方式：

1. **反向推演后回扣**：暂时按某种说法推演其结果，再用事实指出结果与现实之间的差距。
2. **承接后转向**：先接住对方的表述，再用事实或反问显出其中矛盾；不要只靠语气让读者猜测。

## boundary_conditions

涉及安全、医疗、法律和跨文化传播时，不把反讽当作唯一的事实表达；没有共同语境就改用直接判断。

反讽只承担表达态度的作用；事实、数字和未决信息仍应直接说明，**反讽不承担举证责任**。

## overuse_risk

反讽密集会制造犬儒距离、误读和对人的攻击，也会把作者的真实立场藏掉。

反讽应针对可说明的说法或行为。涉及未经证实的个人关系时，先交代不确定性；不要把矛盾转成人身攻击。

## repair_strategy

问“读者是否能指出反讽针对的命题和证据”；若不能，改成直接陈述、对照或让步，不靠语气赌理解。
