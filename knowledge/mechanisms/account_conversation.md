# Account Conversation · 账号级对话

```yaml
id: mech.account_conversation
name: 账号级对话
function: 把同一账号的多篇发布视为与长期读者的一场持续对话，管理跨篇的预期、回访与变化
confidence: contextual
```

## definition

单篇文章是作者与想象读者的一次会话；一个持续发布的账号，是与老读者的一场长期对话。
老读者不是每篇都冷启动的陌生人——他读过你之前的文章，记得你的开头方式、
常用骨架和收尾动作。账号级对话机制负责在这个时间尺度上维持在场感：
什么应该稳定（判断方式、价值取向、事实纪律），什么应该变化（开头类型、骨架、
修辞形式、收尾动作）。

## mechanism

对话的一方重复同一套话术时，对话感就会流失——与话轮中"每次回应都给对方新东西"
同理。因此：

1. **稳定层**：作者的判断力、立场方式、分寸习惯跨篇一致，这是账号被信任的底座；
2. **变化层**：表达动作（进入方式、结构选择、强化形式、结尾方式）随内容与近期历史主动变化，
   避免读者对"形式"形成预期后把预期当噪音；
3. **回访层**：新文章可以回指自己此前的真实发布（"上次那篇之后，又有读者问……"），
   形成话题回访（topic return），但只在真实相关时使用，不制造虚假的连续剧感。

## realizations

- **成文前**：回顾账号近期 3–5 篇，列出已使用的开头类型 / 骨架 / 首节标题句式 /
  收尾动作 / 强化形式，作为本次候选策略的约束条件；
- **成文中**：上一篇用过的感悟句型、收束句式不进入本篇候选；
- **系列内容**：识别度交给栏目名、固定信息位置（如文末来源清单）承担，
  表达动作仍然变化；
- **跨平台**：同一内容在 X 与公众号的差异化改写，同时参考两个平台各自的近期历史。

## boundary_conditions

本机制只适用于有持续发布记录的账号任务；单篇委托、新账号首篇、
或无法获得历史发布记录时，退化为单篇机制集合，不虚构"近期文章"。
变化层的目的是服务老读者的阅读体验，不是为了不同而不同——
如果某种结构确实是当前材料的最佳解，且近期未用，照旧使用。

## overuse_risk

- 把"账号级变化"执行成刻意规避一切重复，损伤稳定声音；
- 虚构与历史文章的关联（"上次说过"但上次没说）；
- 见 `../anti_patterns/account_level_monotony.md`（本机制的对照病灶）。

## repair_strategy

发现跨篇同构时，不必推翻已发文章；从下一篇起，在候选策略阶段加入
"与近期文章的差异度"标准即可。账号级修复靠迭代，不靠改写历史。
