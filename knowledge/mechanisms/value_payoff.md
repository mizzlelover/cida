# Value Payoff · 读者价值兑现

```yaml
id: mech.value_payoff
name: 读者价值兑现
function: 在阅读或收听过程中持续提供真实新增值，使继续来自获得而非拖欠
confidence: contextual
```

## definition

价值兑现是读者在某个内容单元实际得到的判断、事实、解释、证据、方法、经验、
情感理解或视角变化。它检查“读到这里已经得到什么”，与句子是否漂亮、信息是否密集不是同一件事。

## mechanism

先标出入口约定，再为主要内容单元分配不同的价值职责。前段尽早完成第一次真实兑现，
后续单元新增价值并自然打开下一项认知任务，结尾形成综合、行动、边界或讨论空间。
续读来自“已经有所得，且知道还有具体问题会被推进”，不是靠故意不说完。

## realizations

- **论证**：关键理由 → 证据 → 反方 → 条件化结论，各自提供不同获得；
- **教程**：选择方向 → 第一步 → 失败点 → 验证方法，避免只有步骤名没有操作信息；
- **叙事**：具体处境 → 变化 → 发现 → 机制或回看，场景本身也承担理解价值；
- **视频/播客**：按时段或章节检查观众获得，画面与声音共同完成展示和解释；
- **微博/短帖**：一次集中兑现即可，不为多个峰值重复同一判断。

## boundary_conditions

共情、叙事和复杂推理允许较低表层信息密度，不能把每段都改成结论或干货清单。
长文不需要每个段落都有“爆点”，但连续单元不能只有同义重复与自我预告。
不伪造“首次兑现”所必需的数据、经历、演示或结果。

## overuse_risk

机械追求每段一个答案会破坏叙事和推理；把价值兑现理解为刺激密度，
会造成清单化、金句通胀和价值拖欠的另一种变体。见 `../anti_patterns/value_delay.md`。

## repair_strategy

逐单元写“读后新增什么”。若连续两项答案相同，合并、删除或补入不同任务；
若前段只有背景与预告，把最有价值且不妨碍理解的真实材料前移；
若结尾才首次出现核心价值，重排结构而不是在前文加更多钩子。
