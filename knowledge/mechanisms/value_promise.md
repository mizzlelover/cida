# Value Promise · 读者价值约定

```yaml
id: mech.value_promise
name: 读者价值约定
function: 让读者知道继续阅读能获得什么，并以正文可兑现的价值建立预期
confidence: contextual
```

## definition

价值约定是文本与读者之间的任务承诺：这与我有何关系，继续读能得到什么。
它可以表现为明确答案、方法、证据、经验、解释或理解变化，不等于标题刺激，也不要求把全部结论塞在开头。

## mechanism

先确定读者、入口和材料，再选择正文确实能够兑现的收益。开头建立相关性与预期，
前段用首次实际获得证明约定可信，后续逐步完成剩余认知任务。
约定的强度不得超过材料：有结果才承诺结果，只有经验就承诺经验与边界。

## realizations

- **文章**：标题、开头与正文对准同一个问题或判断，尽早给关键理由或材料；
- **教程**：说明能解决什么、适合谁，前段先给可用的一步或选择方向；
- **经验内容**：承诺可借鉴的过程、失败点和条件，不承诺人人都能复现的结果；
- **视频/播客**：用可听见的对象、问题、演示或场景建立约定，并尽快给第一次兑现；
- **社群**：直接说明与共同任务的关系，不对熟人演冷启动广告。

## boundary_conditions

文学叙事、深度报道和探索性谈话可以延迟完整答案，但不能延迟真实价值；
场景、人物、氛围和疑问本身必须有材料、有作用。未指定传播目标时不强行制造收益承诺。
普通但实用的内容不需要包装成“必看”“颠覆”或“终极”。

## overuse_risk

夸大结果、标题与正文各说各话、不断预告“后面重点”、把收益写成刺激，
会造成空头承诺与价值拖欠。见 `../anti_patterns/value_delay.md`。

## repair_strategy

写出一句“读者读完会真正得到什么”，核对开头是否说清、前段是否开始兑现、结尾是否完成。
若正文撑不住，降低承诺、补真实材料或重选角度；不要只加强标题和钩子。
