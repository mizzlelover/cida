# 通用阅读情境（generic）

用于未指定平台、一般屏幕阅读或只需要把内容写清楚的任务。不要虚构平台入口、算法和互动目标，
也不要为了“像自媒体”强行加快、切碎或加金句。

## 1. 任务契约

优先确认读者、文章用途、内容形态和篇幅。入口与关系未知时标 `unknown`，采用能独立成立的写法：
背景不过度依赖共同语境，术语按读者知识解释，核心判断不依赖标题党或外部对话。

一般文章可从 `STYLE_SYSTEM.md` 的回退 Profile 开始；学术、公文、文学、演讲等体裁使用各自合法语域，
不受“高质量对话型”数值限制。

## 2. 候选结构

根据材料比较，而非固定套版：

- **判断—解释—证据—边界**：适合观点、评论与复杂解释；
- **真实场景—发现—机制—应用**：适合经验能改变理解的材料；
- **问题—关键原因—方法—适用条件**：适合实用与教程内容；
- **材料本身已足够时保留原结构**：不为变化而变化。

完整任务至少比较两种入口或信息顺序。候选差异必须影响读者获得，不只是换标题。

## 3. 价值兑现

- 开头让读者尽快知道对象、问题及与自己的关系；
- 前段给一次真实获得：关键判断、解释、证据、方法或有意义的场景；
- 中段每个单元新增内容，不用同义重述等待结尾；
- 结尾完成判断、行动、综合或视角变化，不机械总结全文。

短文本可以只有一次集中兑现，不强行设置多个“钩子”。

## 4. 屏幕与语言表达

- 段落以完整表意和换气为准；扫读场景中让段首承担真实信息，但不强制每段同序；
- 小标题在内容需要导航时出现，能共同还原主线；不以固定字数机械切分；
- 列表只用于真实并列、步骤或选择；加粗只标真正需要被看见的内容；
- 开头可直陈、场景、疑问、冲突或叙事，选择依据是材料与任务，不是“直陈才自然”；
- 关键判断可以独立成段，其他地方保持自然节奏。

## 5. 验收

- 未指定平台时，文本是否仍能独立成立？
- 是否给读者持续的新获得，而不是只做到通顺完整？
- 结构是否来自内容，段长、小标题和列表是否各有功能？
- 事实、证据、立场和分寸是否保留？

## 铁律

通用不是“所有场景共用的最佳文体”，只是缺少更多任务信息时的诚实回退。
逻辑、判断、证据和思想复杂度不因屏幕阅读而打折。
