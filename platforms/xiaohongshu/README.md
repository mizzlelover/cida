# 小红书图文笔记（xiaohongshu）

用于小红书图文、经验笔记与知识型笔记。视频任务转入 `platforms/video_script/`，
同时在任务契约中记录 `platform: xiaohongshu`。核心是入口分流、真实具体与可使用价值，
不是统一缩短、加 emoji 或模仿某种亲昵口吻。

## 1. 先分入口、形态与材料

```yaml
surface: 图文笔记 / 经验记录 / 教程 / 测评或比较 / 观点笔记
entry_route: search / recommend / follow / unknown
reader_relation: 带着具体问题的人 / 信息流中的陌生人 / 已关注的人
```

- `search`：标题和首句对准具体问题；先给答案、结果或选择方向，并尽早交代适用条件。
- `recommend`：从目标读者正在经历的具体矛盾、场景或真实结果进入；让陌生人立即知道“这说的是我什么事”。
- `follow`：可承接系列与既有经验，但单篇仍有完整价值，不要求读者先补历史内容。
- `unknown`：选择具体问题与场景都能理解的入口，不声称兼顾所有流量入口。

材料需求随形态变化：经验需要真实过程与细节，教程需要步骤和条件，测评需要共同比较尺度，
观点需要真实判断与依据。缺哪类材料就补哪类，不用数字和清单伪造经验。

## 2. 原生基线

```yaml
orality: 6–9
intimacy: 5–8
information_density: 6–9
concreteness: 高，但只使用真实细节
block_length: 轻而完整
entry_speed: 快落到对象、问题、结果或场景
reader_interaction: 5–8
```

“具体”不等于数字越多越好，“亲近”不等于称呼亲密。短块服务手机阅读，
不能把完整步骤切成无法使用的碎片；emoji 只在确有视觉分隔功能时少量使用。

## 3. 候选结构

- **结果/发现—过程—条件**：先给真实结果或发现 → 关键过程 → 哪些条件影响复现。
  适合确有经历或结果的材料；没有结果就不写结果型开头。
- **问题—误区—方法—验证**：对准具体问题 → 指出常见无效做法 → 给步骤 → 说明如何判断是否有效。
  适合教程与问题解决。
- **共同尺度比较—差异—选择**：先确定比较对象和标准 → 给关键差异 → 按不同读者条件给选择。
  适合测评、选购与方案比较，不用无法核实的参数。
- **小场景—经验发现—适用边界**：用具体经历建立连接 → 提炼发现 → 说明不能推广到哪里。
  适合经验与观点笔记。

## 4. 价值兑现与发布单元

- 标题、封面文案（如需要）、首句和正文必须兑现同一件事，不各说各话；
- 前段先给可用答案、真实发现或关键经验，不用长篇自我介绍证明“我有资格”；
- 中段给步骤、失败点、选择依据、前后差异或具体场景，避免只写正确感想；
- 收藏级价值来自可复用的清单、条件、步骤和提醒，不写“建议收藏”来代替；
- 结尾可给适用边界、行动建议或一个具体问题，不硬加“姐妹们怎么看”。

完整发布任务按用户需要交付标题、正文和封面短文案；未要求物料时只写正文。
标题数量或候选稿件只在用户要求时展示。

## 5. 验收

- 搜索型是否真正回答查询，推荐型是否迅速建立具体处境，关注型是否不依赖旧文？
- 删掉昵称、emoji 和短段后，是否仍有真实经验或实用价值？
- 每个数字、结果、对比和“我试过”是否有来源？
- 读者能否根据条件判断方法是否适合自己，而不是只看到统一结论？

## 反平台腔

警惕“姐妹们”式假亲昵、焦虑贩卖、“不看后悔”、虚构前后对比、伪造体验、
参数表堆砌和模板化救命文学。真实感来自真实细节与诚实边界，不来自语气词。
