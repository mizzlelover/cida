# 微博短帖与长文（weibo）

把微博当作信息流中的可见内容单元：读者可能只看到首句、首段或截图。
核心是让核心判断在可见单元内自足，后续展开提供真实增量，而不是用半截话钓鱼。

## 1. 先分形态与可见范围

```yaml
surface: short_post / long_post / thread
entry_route: recommend / follow / share / search / unknown
visible_unit: 首句 / 首段 / 展开前 / 截图句 / 整条
```

- `short_post`：集中一个判断、事实或观察，不把多篇文章压成电报。
- `long_post`：展开前已经成立，展开后补证据、背景、反方或行动；不能靠展开才能纠正误导。
- `thread`：每条尽量承担一个完整任务，同时保留顺序导航；不把单句随机切成多条。
- 入口未知时优先自足，不依赖共同语境、粉圈暗语或下一条才能理解。

## 2. 原生基线

```yaml
entry_speed: 快速落到核心判断、事实或冲突
information_density: 高，但保留必要限定与关系成分
structure: 浅层；层级服务理解，不机械限定层数
judgment_strength: 与证据匹配
rhetorical_density: 克制，把峰值放在最值得独立记住的位置
```

锋利来自判断和材料，不来自愤怒、绝对化和省略条件。

## 3. 候选结构

- **判断—最关键依据—必要边界**：适合观点与评论；
- **事实/对照—意义—判断**：适合有强事实或反差的材料；
- **具体观察—机制命名—适用对象**：适合从生活或现场观察进入；
- **可见摘要—分层展开**：适合长文，可见摘要本身能回答或说明问题。

候选比较时先问“哪个核心内容最值得被看见”，而不是“哪句最冲”。

## 4. 价值兑现与传播边界

- 首个可见单元提供核心获得，不用“懂的都懂”“下一条说重点”拖延；
- 中段每一层增加证据、解释或背景，不把同一判断换措辞重复；
- 可能被截图的句子尽量能独立成立，脱离上下文不反转原意；
- 转发价值来自可压缩的判断、证据或观察，不以“不转不是……”勒索；
- 结尾可落判断、行动或问题，避免多余总结和情绪加码。

## 5. 验收

分别只读首句、展开前和可能被截图的句子：是否清楚、基本自足、没有误导？
长文展开后是否有实质增量？删掉限定是否会让判断更绝对？
若只把段落变短、语气变冲，而信息顺序没有变化，平台适配不通过。

## 反平台腔

警惕震惊体、半截话钓鱼、情绪勒索、故意隐去关键条件、伪冲突和为立场而立场。
不为了截图传播牺牲证据、分寸和完整含义。
