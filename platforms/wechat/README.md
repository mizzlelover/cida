# 微信公众号文章（wechat）

把公众号长文当作连续的移动端阅读过程，而不是一篇排得较短的通用文章。
核心任务是持续相关性与读完价值；不使用未经证实的推荐、读完率或流量断言。

## 1. 先分入口与关系

```yaml
surface: article
entry_route: follow / share / search / recommend / unknown
reader_relation: 关注者 / 被转发带来的陌生读者 / 专业读者 / 混合
```

- `follow`：可利用合理的账号共同背景，但新读者仍应能进入；延续账号长期价值，不每篇重启自我宣传。
- `share`：首屏脱离转发者的补充说明也能成立，迅速交代对象、问题和价值。
- `search`：标题与开头对准具体问题，先给回答方向和必要定义，再展开脉络。
- `recommend/unknown`：不猜算法；让标题、首屏和正文形成一致、可独立理解的价值约定。

## 2. 原生基线

```yaml
orality: 5–7
information_density: 6–8
logical_explicitness: 6–9
reader_interaction: 5–8
narrative_presence: 按材料
paragraph_length: 完整短段为主，不切碎
subheading: 按意义单元与导航需要设置
```

不执行“每多少字必须一个小标题”“峰值不能放段中”等机械配额。
小标题可以是判断、问题或有信息量的指引；扫读小标题应能还原主线，不要求全部同一语法结构。

## 3. 候选结构

- **核心判断先行**：首屏给判断与读者代价/收益 → 关键证据 → 反方或条件 → 综合。
  适合已有明确论点的评论与分析。
- **具体场景进入**：首屏呈现真实矛盾 → 事件中的发现 → 机制解释 → 回到读者处境。
  适合有现场、人物或经历的材料；故事必须改变理解。
- **问题与解决路径**：对准具体问题 → 先给可用结论或第一步 → 展开原因与方法 → 给适用条件。
  适合教程、经验与实用长文。

选择后重排材料，不把原通用稿的三个部分原样保留再补标题。

## 4. 标题—首屏—中段—结尾

### 标题与首屏

- 标题说清值得读的对象、问题或判断，不用正文无法兑现的夸张；
- 首屏尽快提供具体问题、核心矛盾或有信息量的判断，并给一次初步获得；
- 不用“今天聊聊”“本文将从三方面”等自我预告替代内容。

### 中段

- 每个小节至少新增一种价值：事实、证据、解释、方法、反例、场景或视角；
- 在连续解释后安排具体材料，在高密度信息后给必要换气；
- 小节结尾可以落判断，但不为每节制造金句；
- 发现连续两段只证明同一件事时，合并、删除或补新的论证任务。

### 结尾

给完成价值：综合判断、可执行行动、适用边界、真正开放的问题或视角变化。
“转发给需要的人”“建议收藏”不能替代完成价值。

## 5. 交付与验收

用户需要完整发布稿时，标题与正文是必要单元；摘要、封面文案等只在要求时生成。
验收：标题与正文约定一致；首屏可独立进入；中段持续有增量；小标题能导航；
结尾值得；陌生读者不会因缺失共同背景而迷路。

## 反平台腔

警惕震惊体、强行升华、“深度好文”自封、情绪化标题、乞讨式收藏转发、表情符号堆砌。
也警惕把“反标题党”执行成标题没有信息、开头只有姿态、正文要求读者先付出大量耐心。
