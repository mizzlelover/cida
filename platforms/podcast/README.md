# 播客稿适配器（podcast）

## 本质区别

播客是**长程听觉跟随**：听众常常伴随性收听（通勤、家务），
注意力有波动。稿件要允许"中途掉队的人随时回来"。

## 参数偏移

```
orality:            8（自然的对话节奏）
topic_return:       关键——话题岔出去必须回得来，且有回环信号
recap:              定期收拢（"我们说到哪了？说到……"）
preparedness:       semi_prepared——有大纲，留出即兴空间
```

## 专项规则

1. **话题回环设计**：主干话题 + 支线漫游；每个支线出口处写回归信号；
2. **定期收拢**：每 10–15 分钟的内容需要一个 30 秒的"我们在哪"小结；
3. **对话稿 vs 独白稿**：对话稿要写清分工（谁追问、谁补充），
   独白稿参照 video_script 但节奏更缓；
4. **知识型播客的密度管理**：参考"声东击西""忽左忽右"类节目的
   知识密度——信息要成串，但串与串之间要有气口；
5. **口语真实性的尺度**：保留自然的追问与自我修正，删除纯填充。

## 边界

Podcast Rambling（散漫无结构）是失败模式：自然松散是**表层**，
底层话题结构必须成立（见 `knowledge/mechanisms/topic_progression.md`）。
