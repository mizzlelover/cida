# 社群长文与社群消息（community）

用于微信群、企业社群、兴趣社区、会员社区等具有共同背景或持续关系的发布场景。
核心不是冷启动抢注意，而是让成员迅速知道“这与我、与这个群有什么关系”，并提供可行动、
可回应或值得保存的内容。不要把社群当成语气更随便的公众号。

## 1. 先确定关系与共同背景

```yaml
platform: 实际社群工具或社区
surface: announcement / discussion / experience / tutorial / recap / long_post
entry_route: direct / follow / share
reader_relation: 熟人 / 同好 / 同事 / 学员 / 会员 / 管理者与成员
shared_context: 可以省略的共同背景
missing_context: 为潜水成员或新成员必须补齐的信息
privacy_boundary: 不宜公开的人名、截图、发言与内部资料
```

- 管理者发布要分清通知、请求与讨论，不用权威语气包装普通个人观点；
- 成员分享要避免默认所有人都知道前情，也不反复介绍人人皆知的背景；
- 转发进群的内容要补一句与群任务相关的理由，而不是只丢链接或长文。

## 2. 原生基线

```yaml
formality: 2–7
orality: 4–9
intimacy: 由真实关系决定
information_density: 以任务够用为准
signposting: 行动、时间、对象与责任清楚
reader_interaction: 有具体问题或协作需要时提高
```

亲近不等于叫昵称，轻松不等于含糊。通知要准确，讨论要有空间，经验要有细节，
教程要有步骤，活动或协作内容要写明对象、行动与必要条件。

## 3. 候选结构

- **结论/事项—原因—行动**：适合通知、协作与实用信息；
- **共同问题—新信息/经验—建议—讨论点**：适合知识分享与问题解决；
- **真实经历—关键发现—对成员的价值**：适合经验复盘，避免只讲自己；
- **背景简述—分歧/选择—具体提问**：适合讨论，提问必须能引导实际回应。

不要因为社群关系近就省略价值设计；也不要把面向陌生流量平台的钩子搬进来。

## 4. 价值兑现与互动

- 开头直接交代与群成员有关的事项、问题或材料，不硬演“震惊体”冷开场；
- 前段给关键结论、资源、方法或经验，不用大段客套和自我证明；
- 中段保留行动所需条件、时间、对象、步骤或证据，减少成员追问成本；
- 讨论型结尾提出一个具体、可回答、与共同经验有关的问题，不用“大家怎么看”敷衍；
- 行动型结尾写清下一步，不以群压力、接龙羞耻或虚假紧迫感逼迫参与；
- 资源与收藏内容以准确、可检索和可复用为主，不乞讨保存。

## 5. 验收

- 新成员或漏看前文的成员能否理解必要背景？
- 成员读完是否知道这与自己何关、下一步是什么、在哪里补充信息？
- 讨论问题是否具体且允许多种真实回答？
- 是否泄露他人发言、个人信息或内部资料？
- 去掉群昵称和表情后，内容是否仍有明确价值？

## 反社群腔

警惕领导讲话腔、通知腔、知识服务腔、假亲热、过长寒暄、无差别“@所有人”、
情绪动员和模糊行动要求。社群感来自真实关系与共同任务，不来自语气词。
