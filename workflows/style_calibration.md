# Calibrate：个人风格校准（style_calibration）

从用户自己的真实样本学习稳定声音与可迁移表达动作，再按不同任务和平台调整。
学参数与机制，不抄句子；个人 Profile 不是覆盖所有场景的统一滤镜。

## 1. 采样：同时寻找稳定与变化

请用户提供几篇自己满意的真实文本，最好包含不同平台、体裁或写作时期。
样本不足时先形成可调整初稿，不把一篇文本的习惯上升为稳定人格。

为每个样本记录：发布场景、读者、用途、内容形态、用户满意之处。
区分：

- **稳定声音**：跨样本仍在的判断方式、作者距离、节奏、经验使用和价值取向；
- **场景策略**：只在某平台或体裁出现的开头、结构和互动方式；
- **偶发习惯**：单篇题材、编辑要求或临时状态造成的表层特征。

## 2. 特征抽取

使用 `STYLE_SYSTEM.md` 的十维参数描述倾向，并为判断附上样本证据：

```yaml
formality:
orality:
information_density:
logical_explicitness:
intimacy:
rhetorical_density:
judgment_strength:
rhythmic_variation:
narrative_presence:
reader_interaction:
```

另抽取：

- 典型开头与结尾、段落和小标题习惯、标点与比喻来源域；
- 如何使用经验、证据、限定、幽默、自我修正和读者回应；
- 哪些表达动作带来真实价值，哪些只是用户自己喜欢但可能增加读者成本；
- 同一个人在不同平台上哪些部分变化、哪些部分始终不变。

## 3. 形成 Personal Style Profile

```yaml
profile_name:
stable_voice:        # 跨场景保留的声音与作者位置
parameters:          # 十维倾向及适用范围
signature_moves:     # 可迁移表达动作，不复制原句或人格化指纹
platform_variants:   # 已观察到的场景化差异，不编造未见过平台的习惯
boundary_notes:      # 依赖语境的习惯、失效条件和保真边界
sample_evidence:     # 各判断对应的样本位置
```

`signature_moves` 可以是“先讲一个小场景再进入判断”“段末用短句收束”，
不能是复制固定句式、口头禅或某个在世作者的个人风格。

## 4. 应用到任务契约与候选选择

应用顺序：事实与立场 → 内容目标 → 平台任务契约 → 平台原生基线 → Personal Style Profile。
契约字段与缺失信息处理见 `workflows/platform_task_contract.md`。

- 用稳定声音帮助选择材料、作者距离和表达动作；
- 用场景参数调整语域，不覆盖入口、内容形态和读者关系；
- 多个候选在任务上都能成立时，可用个人 Profile 选择更像用户的一版；
- 不用个人偏好裁定事实、逻辑和平台适配质量，不把“用户习惯”当成无效表达的理由；
- 风格与任务冲突时保留人格线索，调整表层习惯，并说明关键取舍。

## 5. 反馈与修正

收到用户反馈时，先判断它属于稳定偏好、某次任务修正还是平台差异。
新样本或反例可以修正 Profile；不要因一次“再口语一点”就永久提高所有任务的 Orality。
记录适合与不适合的场景，让校准包含边界，而不只是越来越多规则。

## 6. 边界

- 对用户自己的文本可提取高层特征和可复用动作，不复制大段原文；
- 对在世作者样本只提取高层属性，输出不声称“某某风格”，不复制个人语言指纹；
- 不创建“永远这样开头”“所有平台同一语气”的绝对规则；
- Profile 是带证据和适用范围的参考，不是枷锁，也不是传播效果保证。
