# Deep Rewrite · 深度重写工作流

用于长篇、高模板、严重结构失衡、素材散落或需要重建平台策略的文本。
在 `workflows/rewrite_article.md` 基础上，强制执行素材地图、候选比较和价值兑现设计。

## 输入与输出

```yaml
input:           # 原文或经授权的转录
task_contract:   # workflows/platform_task_contract.md
rewrite_level: deep
```

默认输出重写稿与三行以内关键取舍摘要。Explain 模式展开十二项诊断、候选比较、
素材缺口和机制边界。仍待确认的信息单独标明。

## 0. 建立保真层与任务层

### 保真层

列出事实、数据、直接引语、核心立场、必要推理、限定、个人声音和授权范围。
遇到转录先核对专有名词、数字、引语与识别疑点，不擅自补全。

### 任务层

按 `workflows/platform_task_contract.md` 确定新读者、新入口、内容形态、目标与格式。
原文用途与新用途分开记录，避免把“原文本来很好”和“需要为新场景重建”误判成矛盾。

## 1. P0：绘制主张—证据—素材地图

```text
主判断
  ├─ 支撑事实 / 经验 / 例子
  ├─ 推理桥与隐含前提
  ├─ 限定条件与反方疑问
  ├─ 独有材料：现场、细节、专业位置、可核验结果
  └─ 通用材料：常识、万能例子、同义反复、空泛感想
```

- 先修错误归因、跳步和证据错配；
- 标出“只有好处没有代价”“观点很大材料很小”“每段证明同一件事”等断点；
- 原文没有判断时先补判断；有判断但缺独特或充分材料时，补料、收缩或说明限制；
- 不因追求自然、速度或平台效果删除现实复杂度。

## 2. P1A：生成并比较重建方案

内部形成 2–3 个方案，至少改变两项：主入口、首份材料、主判断呈现、读者问题、
信息顺序、叙事/论证结构、价值类型。每个方案标出：

```yaml
keeps:           # 保留哪些原文优势
changes:         # 改变哪些结构与材料职责
reader_gain:     # 读者比原稿多获得什么
platform_fit:    # 如何符合入口、形态和关系
evidence_risk:   # 是否可能超出材料或丢失限定
```

选择最能同时满足保真、任务和材料强度的方案，而不是变化最大或最刺激的方案。

## 3. P1B：重建结构与价值兑现

- 按新读者的认知顺序与入口重排，不按原段落顺序搬运；
- 标出入口相关性、价值约定、首次兑现、每个主要单元的新增值和完成价值；
- 每段承担不同职责，避免机械三点、等长段落和每段同一语法开头；
- 读者可能反驳之处补限定或证据，读者可能失去兴趣之处先检查价值是否重复，
  不用机械钩子遮盖；
- 保留原文有效的场景、论证、例子和收束，不为“深度”全部推倒。

## 4. P2–P4：表达、节奏与峰值

- 连接词只保留真实转折、因果、让步或共同注意功能；
- 名词化、长定语和被动堆积按读者与媒介拆解；
- 句长变化由意义推动，听觉文本另做呼吸与指代检查；
- 开头形式服务任务和材料，不把直陈当成唯一自然形式；
- 通过 `rhetorical_peak` 的 Quote-worthiness Filter 保留少量承重峰值；
- 结尾完成判断、行动、留问或回扣，不重复前文或强行升华。

## 5. 双重交付检查

```text
□ 原意、核心立场、必要证据、分寸和声音均保留
□ 素材足以支撑新承诺；不足处已补料、收缩或说明
□ 候选比较真实发生，选中方案与成稿一致
□ 结构变化解决已诊断的问题，首次兑现与中段增量清楚
□ 目标平台、内容形态、入口和读者关系对齐
□ 跨平台时有实质差异；未指定平台时不强行制造平台腔
□ 直接引语、数据、限定词和作者位置得到保留
```

任一项不通过，回到对应阶段修订。文本本来清楚完整且适合用途时，不为制造改动而重写。
