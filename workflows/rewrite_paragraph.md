# Workflow C：段落优化（rewrite_paragraph）

针对一个或几个段落的精细优化。保留作者原意，不把局部任务擅自升级为平台重写。
如果段落承担首屏、核心论证、首次兑现或结尾职责，先读取它在全文中的任务再改。

## 1. 局部任务与知识检索

先确定：段落说什么、在全文承担什么功能、读者读到这里已经知道什么、目标媒介是什么。
平台职责影响局部表达时，按 `workflows/platform_task_contract.md` 读取已经明确的字段，不把局部任务扩成整篇重写。
再从 `knowledge/mechanisms/GRAPH.md` 选择最小正向修复机制，最后按症状查
`knowledge/anti_patterns/README.md`。需要语域或节奏判断时读取 `STYLE_SYSTEM.md`。
口述材料按 `workflows/oral_to_article.md` 核对保真边界。

局部优化通常只需一个修复策略，不机械生成三稿；如果存在两种实质不同的信息顺序，
可内部比较后选择更符合作者论证与读者任务的一版。

## 2. 处理优先级

### clarify：弄清到底在说什么

找出歧义、含混和代词悬空。两种读法都成立时，选择符合作者论证方向的解释或向用户确认。
拆开超出工作记忆的长定语和嵌套从句，但不把复杂关系切错。

### compress：压缩无效努力

删除同义反复、空修饰和不增加价值的自我指涉。目标是单位读者努力获得更多意义，
不是越短越好；信息密度上升时，理解成本必须下降，必要关系和限定不能删。

### reorder：调整内部顺序与价值位置

- 句内检查已知/新信息和中文信息尾重，段内检查话题链与主语跳转；
- 先结论还是先铺垫由读者反对成本、期待和材料决定；
- 开头段检查相关性与真实约定，中段检查是否新增值，结尾段检查是否完成任务；
- 局部段落不新增观点，发现论证缺环时标注或升级到整篇重写。

### connect：衔接

能用语义关系衔接时不加连接词；连接词留给真实转折、因果、让步和共同注意。
段间优先通过论证与话题关系转场，慎用“接下来”“下面”“值得注意的是”。

### rhythm：节奏

默读或朗读，检查呼吸、拖沓和停顿。句长变化由意义、屏幕或听觉推动；
重点可短句落实，复杂铺陈可以长，不为了“像人”随机切碎。

### polish：打磨

动词优先于无功能名词化，具体优先于空泛抽象，术语保持准确。
具体化只能使用原材料或可核实信息，不补编数字和经历。

## 3. 边界与升级条件

- 保留作者的语气习惯，除非它伤害清晰度、任务或事实；
- 如果开始改变核心观点、全文结构或大部分材料职责，升级到 Workflow B；
- 实质改写超过约 40% 时提醒用户考虑整篇重写。比例按实质改写字数 ÷ 原文字数估算，
  只作升级提示，不作为质量分数；
- 平台任务导致局部改动无法解决时，明确说明需要整篇或平台重建，不反复修饰同一段。

## 4. 输出

交付优化后的段落，简要说明关键改动的原文/任务依据、原因和真实机制边界。
纯措辞微调不逐项展开；机制依据无法确认时不编造引用。
