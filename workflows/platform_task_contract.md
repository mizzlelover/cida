# 平台任务契约（Platform Task Contract）

在写作、深度重写、口述成文或平台适配前建立本契约。它决定“为何在此刻对这个读者，
以这种内容形态表达”。短句或段落微调可只读取上下文中已经明确的字段，不机械补表。

## 1. 先固定边界，再开放表达

### 不可随意改变

- 已核实的事实、数据、引语与来源；
- 作者真正认可的立场、核心推理、限定和不确定性；
- 用户要求保留的要点、个人声音、隐私与授权边界。

### 可以重新设计

- 从哪个读者问题或经验进入；
- 哪个判断、事实、例子先出现；
- 信息顺序、结构、详略、篇幅与视听分工；
- 使用何种真实材料承担入口、解释、证明或记忆；
- 语域、节奏、标题、小标题、互动与结尾动作。

平台适配可以改变表达决策，不能改变事实。重写任务保留核心立场，不等于冻结原文的角度、
段落顺序和详略；主题写作则可以比较不同主判断，但不得为了刺激而选择证据不足的判断。

## 2. 建立任务契约

内部填写下列字段。用户已给出的信息优先；缺失且会实质改变成稿的信息只问最关键的一问，
其余采用保守假设并标记 `assumed` 或 `unknown`，不要把猜测写成平台事实。

```yaml
task_type:          # 写作 / 重写 / 口述成文 / 平台适配 / 风格校准
platform:           # generic / wechat / xiaohongshu / zhihu / weibo / video_script / podcast / community
surface:            # 文章 / 回答 / 图文笔记 / 短帖 / 视频脚本 / 播客 / 社群消息等
entry_route:        # search / recommend / follow / share / direct / unknown
reader:             # 谁读；已知、疑问、抵触、可使用的话语
reader_relation:    # 陌生读者 / 关注者 / 同温层 / 专业共同体 / 熟人社群
content_goal:       # 读完知道、相信、理解或去做什么
reader_value:       # 对这群读者最值得提供的判断、方法、经验、证据或连接
consumption_goal:   # continue / finish / save / share / discuss / none；最多一个主动作
format_constraint:  # 篇幅、时长、首屏、展开前、标题、封面文案、画面等已知限制
materials:          # 可用事实、经验、数据、案例、引语及其来源
voice:              # 作者在场方式与必须保留的声音
assumptions:        # 推断及其不确定性；没有则省略
```

`content_goal` 是内容完成后产生的认识或行动；`consumption_goal` 是阅读过程中的行为。
不要把两者混为一谈，也不要为了互动数字硬加 CTA。没有明确传播目标时填 `none`。

## 3. 做素材上限诊断

在润色前判断素材能否支撑任务：

```yaml
core_claim:          # 真正值得表达的判断；没有则标 missing
support:             # 证据、经验、例子能否支撑；标 sufficient / thin / missing
distinctive_assets:  # 独有经历、现场细节、反常识观察、可核验结果、特殊专业位置
generic_material:    # 换任何人都成立的常识、万能例子、空泛感想
best_reader_value:   # 现有材料中对这个读者最有价值的一项
material_gap:        # 为完成任务仍缺什么；没有则省略
```

- 有观点但都是通用材料时，不得只靠缩短、加金句或换平台腔伪装增量；
- 缺少关键经验或证据时，优先补充真实材料；无法补充则缩小判断或明确交付限制；
- 不为“惊艳”编造经历、数字、冲突、截图、效果或平台规则；
- 普通但实用的内容允许保持普通，不把每篇都强行做成观点爆文。

## 4. 生成并比较候选策略

主题成文、深度重写、完整平台适配、视频与播客脚本，内部生成 **2–3 个实质不同的候选**。
候选至少有两项不同：读者问题、主入口、首份材料、主判断、信息顺序、叙事/论证结构、价值类型。
只换几个词或把同一结构换标题，不算不同候选。

按下列标准选择，不打虚假精确总分：

1. **读者价值**：哪版最早提供真实而有用的获得？
2. **平台任务**：哪版符合入口、形态、关系与消费条件？
3. **材料强度**：哪版使用了最独特、最可核验的材料？
4. **保真与声音**：哪版保留原意、分寸和作者位置？
5. **执行必要度**：哪版用最少复杂结构完成任务？

快速段落优化可只形成一个策略；用户要求多稿时再展示候选。Explain 模式可简述为什么选中、
为什么放弃其他方案。

## 5. 绘制读者价值兑现路线

成稿前用少量内部标记确定价值如何抵达，不把文章只看成论证容器：

```yaml
entry_relevance:   # 入口让读者知道“这和我有什么关系”
value_promise:     # 可以真实兑现的阅读收益；不夸大、不拖欠
first_payoff:      # 前段第一次实际给出的判断、方法、证据或经验
progression:       # 每个后续单元新增什么；同时记录读者此刻的新疑问
continuation:      # 让读者继续的真实理由：未完成但有价值的认知任务
completion_value:  # 读完留下的综合判断、可执行步骤、视角或讨论空间
```

- `promise` 必须在正文兑现；不能用标题党、半截话或虚假悬念骗取消耗；
- `first_payoff` 不等于所有结论都堆在开头，而是尽早给一次真实获得；
- `continuation` 来自“已经得到价值，还知道接下来会得到什么”，不是故意不说完；
- 每个单元可以承担不同价值：新事实、解释、证据、方法、场景、情绪理解或视角变化；
- 修辞密度曲线负责强调，价值兑现路线负责值得读；两者不得互相替代。

## 6. 平台与跨平台验收

指定发布场景时，执行 `SKILL.md` §7 的文本质量与平台适配双自检，并额外做：

- **入口测试**：开头符合实际入口，不让搜索读者绕路，也不对熟人硬演冷启动；
- **兑现测试**：价值约定已兑现，前段不是只有背景、姿态和预告；
- **续读测试**：至少存在真实的后续获得，不靠机械问句或拖延答案维持注意；
- **平台消名测试**：隐去平台名和装饰后，仍能从内容组织辨认阅读情境；辨认不靠黑话和 emoji；
- **跨平台差异测试**：同一内容适配两个场景时，至少在切入、首份材料、信息顺序、详略、
  内容单元或互动方式中有两项实质差异，不能只改段长、称呼和排版；
- **素材上限测试**：成稿的增量来自真实材料与判断，不来自包装强度；
- **行动自然性测试**：收藏、转发、讨论等动作由内容价值自然支持，不保证平台表现。

任一关键项失败，回到对应阶段修复；不要只在最后增加钩子或 CTA。
