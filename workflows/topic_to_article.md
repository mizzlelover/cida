# Workflow A：主题 → 成文（topic_to_article）

从主题、要点、提纲或材料直接生成目标文本。指定发布场景时，直接写目标版本，
不先形成通用稿再做平台换皮。

## 导航

1. 任务契约与素材
2. 主判断或内容任务
3. 候选策略
4. 认知推进与价值兑现
5. 平台基线与个人声音
6. 开头
7. 成文
8. 结尾
9. 双重验收

## 输入

```yaml
topic:          # 主题
materials:      # 事实、经验、数据、案例、引语及来源
key_ideas:      # 必须出现的要点
task_contract:  # 按 workflows/platform_task_contract.md 建立
style_hint:     # 用户风格倾向或 Personal Style Profile
rewrite_level:  # 默认完整写作；局部短稿可压缩候选
```

## 1. 建立契约并检查素材

先读 `workflows/platform_task_contract.md`，确定平台、内容形态、入口、读者关系、目标与格式。
再回答：

- 读者读完应当知道、相信、理解或去做什么？
- 读者为什么现在开始、继续和完成？最值得提供的一项价值是什么？
- 作者凭什么谈这个？哪些事实、经验、现场细节或观察是独特材料？
- 当前只有通用常识时，能否补充材料、缩小题目或改变任务？

缺少关键材料时不编造。可以先说明素材缺口，或写一份承诺与材料相匹配的保守版本。

## 2. 形成有增量的主判断或内容任务

观点型文本把主题压成有取舍的判断，并过四项检查：

1. **可争辩**：不是人人只能赞同的空话；
2. **有依据**：现有材料能支撑，不靠语气补足；
3. **对读者有关**：回答这个入口下的真实问题；
4. **有增量**：不是把题目或常识换一种漂亮说法。

可使用限定词收口、对立面构造或 `reframing`，但不得为了反常而反常。
解释、教程和记录型文本不必强行制造争议，应把内容任务压成具体问题、方法或理解变化。

## 3. 生成并选择候选策略

内部生成 2–3 个候选，至少改变两项：读者问题、主入口、首份材料、主判断、信息顺序、
叙事/论证结构或价值类型。每个候选用几行标记：

```yaml
angle:          # 从哪个问题或判断进入
entry:          # 首句/首屏使用什么真实材料
first_payoff:   # 前段兑现什么
structure:      # 后续如何推进
best_asset:     # 使用哪项最有价值的材料
risk:           # 可能的保真、理解或平台风险
```

按 `workflows/platform_task_contract.md` §4 选择。不要让第一个最稳妥的方案自动胜出，
也不要为了差异选择材料撑不住的方案。用户未要求时只交付选中稿。

## 4. 安排认知推进与价值兑现

把文章理解为作者与读者共同完成的认知过程，同时检查读者的时间是否持续有回报。
可用推进动作：

```text
提出 → 理解 → 质疑 → 澄清 → 深入 → 反转 → 解释 → 举例 → 综合
```

按材料重新组合，不固定模板。为每个主要单元标记：

- 它解决读者什么疑问或认知任务？
- 它新增什么事实、证据、方法、场景、情感理解或视角？
- 下一单元为何值得继续？是否有真实任务，而非故意拖欠答案？

明确逻辑需要显式还是隐含，同时标出入口相关性、价值约定、首次兑现和完成价值。

## 5. 选择平台基线与个人声音

指定场景时先读 `platforms/<平台>/README.md` 的任务分支和候选结构，再设十维参数。
未指定平台才使用 `STYLE_SYSTEM.md` 的回退 Profile。
Personal Style Profile 贯穿选材、作者距离和表达动作，不是最后添加的语气词。
按策略从 `knowledge/mechanisms/GRAPH.md` 取 1–3 个真正相关节点，再检查反模式风险。

## 6. 写开头：相关性与真实约定

开头承担两项职责：迅速建立读者与问题的关系；让读者知道继续读能获得什么。
它可以使用：

- 直接判断或有信息量的事实；
- 具体场景、动作或经验细节；
- 一个真实疑问、冲突或反常观察；
- 一个能被正文兑现的结果或方法承诺。

“直陈”不是唯一合法形式。叙事和悬念必须有真实材料、尽快落到主题并兑现；
倒装、元叙述或抽象标签若只是标题腔则删除。口播和播客另做朗读检查，书面文章不以
“念出来像开口说话”替代平台与读者检验。

## 7. 成文：同时管理两条曲线

- **价值曲线**：前段给一次真实获得，中段持续增加新内容，结尾完成认知或行动任务；
- **修辞曲线**：普通表达托起少数峰值，峰值只强化最值得记住且承重的内容。

具体例子必须真实并帮助理解、检验或迁移。句子长短由意义、屏幕或听觉推动。
比喻必须帮助理解、记忆或情感，三者都不承担就删除。金句不能替代中段的信息增量。

## 8. 结尾：完成价值

从综合判断、行动、原则、真问题、视角变化或回应开头中选择合适动作。
给读者“读完值得”的完成感；需要互动时，让问题或行动从内容自然长出。
不把全文再总结一遍，不用收藏、转发或关注请求替代结尾。

## 9. 双重验收

过 `SKILL.md` §7 和 `workflows/platform_task_contract.md` §6。
检查 Key Ideas 是否全部到场、素材是否支撑承诺、候选选择是否真正执行、
平台版本是否从结构上不同于通用稿。失败时回到素材、候选或结构阶段，不只在句面补救。

## 输出格式

默认输出成稿及三行以内关键取舍说明，包含任务依据和真实机制边界。
Explain 模式可追加任务契约、候选比较、认知/价值路线、Style Profile 与重要修辞依据。
