# Workflow F：平台适配与跨平台重写（platform_adaptation）

把同一内容转成适合特定发布情境的版本。平台适配不是先做一篇通用稿再改排版，而是在事实、
立场和授权边界内，重新选择切入、材料顺序、详略、结构、语域与读者价值兑现方式。

## 1. 两种入口

- **主题先行**：从主题或材料直接写目标平台版本。先进入
  `workflows/platform_task_contract.md`，再进入 `workflows/topic_to_article.md`，不要另写通用初稿。
- **已有文本**：先提取不可随意改变的事实、证据、核心立场、限定、引语与个人声音，
  再建立目标任务契约。原文顺序、标题、角度和详略不是默认证据，均可因任务重建。

只做局部语言优化且未指定平台时，不强行进行平台重写。

## 2. 适配流程

### 0. 固定不变项与素材边界

列出事实、数据、引语、核心立场、限定、必须保留要点、隐私与授权边界。
再按 `workflows/platform_task_contract.md` §3 检查素材上限：如果目标版本需要真实经历、
可核验结果或操作细节，而原文没有，先补料、收缩承诺或说明限制，不编造“平台需要的具体”。

### 1. 建立目标任务契约

至少确定：平台、内容形态、入口、读者关系、内容目标、读者价值、消费目标、格式限制。
关键未知只问最影响成稿的一问；其余记录为假设。读取 `platforms/<平台>/README.md` 的原生任务、
候选结构与验收规则，不只读取参数偏移。

### 2. 诊断原文与平台机会

区分三类问题：

1. **文本本身的问题**：逻辑、证据、重复、语域、节奏；
2. **原发布情境的问题**：原文顺序可能合理，只是不适合新入口或新读者关系；
3. **素材上限的问题**：不是换个平台就能解决，需要新事实、新经验或更小判断。

保留原文已经有效的部分，不为显示适配而全部推倒。

### 3. 生成 2–3 个实质候选

候选至少在两项上不同：读者问题、入口、首份材料、主判断呈现方式、信息顺序、
叙事/论证结构、价值类型。按平台文件允许的结构生成，不把同一篇换成三种标题。

用读者价值、平台任务、材料强度、保真声音和执行必要度选择。Explain 模式可简述取舍。

### 4. 绘制价值兑现路线

标出入口相关性、真实价值约定、前段首次兑现、后续新增值和完成价值。
平台适配必须让读者“边读边得到”，不能只把最刺激的句子挪到第一句，正文却仍是原来的缓慢铺垫。

### 5. 成稿与媒介实现

- 按 P0–P4 执行，平台结构与价值兑现属于 P1，不再等到 P2 才处理；
- 从 `knowledge/mechanisms/GRAPH.md` 按策略选机制，可考虑 `reframing`、`narrative_arc`、
  `concrete_example`、`argument_pivot`、`reader_anticipation`、`rhetorical_peak` 等，
  不把平台检索永远限制为开篇、密度和结尾；
- 按平台文件完成标题/首屏/展开前/视听分工等必要单元；用户未要求时不额外输出整套物料；
- 最后才查反平台腔，避免用平台规则制造新的模板。

### 6. 双重验收

过 `SKILL.md` §7 与 `workflows/platform_task_contract.md` §6。
跨平台任务额外比较：至少两项实质差异来自切入、首份材料、顺序、详略、内容单元或互动方式。
如果只是段长、称呼、emoji 或语气词变化，返回第 3 步。

## 3. 场景速查

| 场景 | 目录 | 原生任务重点 |
|---|---|---|
| 通用 / 未指定 | `platforms/generic/` | 一般阅读情境、内容完整性与价值兑现 |
| 微信公众号 | `platforms/wechat/` | 标题—首屏—中段—结尾的持续相关性与长文读完价值 |
| 小红书 | `platforms/xiaohongshu/` | 搜索/推荐/关注分流，真实具体经验与可使用价值 |
| 知乎 | `platforms/zhihu/` | 问题对准、回答义务、证据链与反方处理 |
| 微博 | `platforms/weibo/` | 信息流中的自足判断、可见单元与截图不失真 |
| 视频口播 | `platforms/video_script/` | 分时段兑现、可听性、视听分工与实际发布平台 |
| 播客 | `platforms/podcast/` | 长程听觉价值、话轮、章节与掉队后重入 |
| 社群 | `platforms/community/` | 共同背景、成员关系、直接相关性与可讨论/可行动内容 |

平台、内容形态和入口分别记录。`video_script` 不是实际平台名；小红书搜索与推荐也不是同一入口。

## 4. 反平台腔与诚实边界

警惕震惊体、假亲昵、资历表演、抖机灵、半截话钓鱼、焦虑贩卖、机械 CTA 和书面腔朗读。
同时警惕“反平台腔”变成所有文本都只说平淡直话：真实场景、幽默、悬念、冲突、叙事和情绪，
只要有材料、有功能、符合关系，都可以使用。

不编造平台算法与流量规律，不保证点击、读完、收藏、转发或涨粉。
平台适配的目标是尊重读者情境并持续兑现价值，不是套用流量模板。

## 5. 输出说明

默认交付目标版本，必要时附标题、首屏或视听表等该平台不可分割的单元。
实质适配用三行以内说明关键结构取舍、任务依据、机制及边界；Explain 模式再展开候选和诊断。
